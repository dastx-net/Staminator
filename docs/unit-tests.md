# Unit-тесты и покрытие

## Требование

Покрытие строк тестами — не менее **95% для всего Rust workspace**, включая `apps/desktop`. Метрика общая для кода, попавшего в отчёт на проверяемой платформе; отдельно проверяйте платформенные ветви на соответствующих ОС. Не исключайте файлы приложения ради достижения порога. Покрытие не доказывает правильность: проверяйте результаты, ошибки и пользовательские сценарии.

Порог — требование к проекту и проверкам доработок. Текущее значение указывается только после измерения. Проверка завершится ошибкой при снижении ниже порога; не отключайте её из-за непокрытого кода.

Первый замер 7 ноября 2026 года на Windows MSVC: **33,35% строк** всего workspace; 25 тестов прошли, порог не достигнут.

Повторный замер 8 ноября 2026 года с `--all-features`: **33,39% строк**, 25 тестов прошли; порог 95% не достигнут.

Замер 8 ноября 2026 года после добавления тестов: **49,30% строк**, 37 тестов прошли; порог 95% не достигнут. Проверены чтение файлов, ошибки и резервная копия профиля, изоляция результатов и сеанс по разобранному уроку. Основной пробел — интерфейс desktop. HTML-отчёт создан командой ниже.

Замер 8 ноября после добавления headless UI-тестов: **95,16% строк**, 73 теста прошли. Команда с порогом 95% прошла на Windows MSVC. Отчёт учитывает инструментированные строки тестовых модулей; процент не равен отдельному покрытию только продуктового кода. Настоящие окна, системный ввод и звук остаются для ручной проверки.

Замер после редактора уроков и добавления фраз: **95,02% строк** на Windows MSVC. Команда с порогом 95% прошла; отчёт включает строки тестов.

## Как писать тесты

Используйте встроенные `#[test]` в `#[cfg(test)] mod tests` рядом с кодом. Проверяйте публичное поведение, границы, ошибки и восстановление, а не внутренние детали. Для времени и случайности передавайте контролируемые значения. Тесты должны быть независимыми и запускаться параллельно; файловые тесты работают в отдельных временных каталогах, не в пользовательском профиле и не в `src/stamina_setup`. Для межмодульных сценариев добавляйте интеграционные тесты в `tests/` соответствующего crate; их выполнение тоже входит в общий отчёт.

При исправлении ошибки добавьте воспроизводящий её тест, если это возможно. Для UI отделяйте правила и состояние от отрисовки; проверяйте их автоматически, а системный ввод, окна, звук и DPI — также вручную. Подробные сценарии перечислены в [плане QA](plan/todo/qa.md).

## Установка и запуск

На машине с закреплённым в проекте Rust один раз установите инструменты:

```powershell
rustup component add llvm-tools-preview
cargo install cargo-llvm-cov --locked
```

После доработки из корня проекта запустите:

```powershell
cargo llvm-cov --workspace --html --fail-under-lines 95
```

Команда запускает тесты workspace, формирует `target/llvm-cov/html/index.html` и возвращает ошибку, если тесты не прошли или покрытие строк ниже 95%. Откройте HTML-файл в браузере: в нём видны покрытые и пропущенные строки. `target/` не включается в Git. Для краткого отчёта в консоли используйте `cargo llvm-cov --workspace --summary-only --fail-under-lines 95`; эта команда повторно запускает тесты.

Инструмент измеряет выполненный код с помощью LLVM. Системные и графические сценарии, код других платформ и качество проверок отдельный процент не гарантирует. При обновлении toolchain убедитесь, что LLVM-компонент установлен для используемой версии Rust.

Документация: [cargo-llvm-cov](https://github.com/taiki-e/cargo-llvm-cov), [покрытие в rustc](https://doc.rust-lang.org/rustc/instrument-coverage.html).

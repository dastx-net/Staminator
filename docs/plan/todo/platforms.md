# Поддержка разных операционных систем

Помимо Windows, приложение должно работать на Linux и, если возможно, на macOS. Нужно проверить сборку и работу на каждой платформе, включая ввод с разных раскладок, отдельные окна, сохранение их положения, звук и файловые диалоги.

**Предложение:** по возможности использовать общие кроссплатформенные компоненты и отдельно проверять системные особенности. Стоит решить, какие версии систем поддерживать и как распространять сборки; доступность macOS для сборки и проверки пока неизвестна.

## Аналитика первой очереди

**Оригинал:** это Win32/MFC-приложение; `MainWnd.cpp::OnChar` обрабатывает ввод Windows, `Stamina.cpp::LoadLayouts` использует системные раскладки, `KeybWnd.cpp` управляет отдельным окном. Поведение Linux/macOS из оригинала не следует и должно быть определено и проверено для клона.

**Сейчас:** `eframe`/`egui` и `rfd` используются в desktop-приложении, но наличие кроссплатформенных библиотек не подтверждает работоспособность приложения на каждой ОС. `user_store.rs::default_path` имеет Windows и XDG-ветви, отдельного пути macOS нет; звук и получение раскладки требуют проверки по исходникам и на реальных системах.

**Реализация.** Оставить ядро и форматы независимыми от ОС; обращения к каталогам, вводу, окнам, диалогам и звуку изолировать за адаптерами. Для каталогов использовать системные соглашения Windows, XDG Linux и macOS, без незаметного отката в временную директорию при ошибке. Обрабатывать текстовый Unicode-ввод отдельно от физических клавиш управления; IME и dead keys проверять на реальных системах. Экранную клавиатуру связывать с доступной информацией о раскладке и явно сообщать об ограничениях. В CI добавить сборку и тесты workspace на Windows и Linux, macOS при доступном runner; зафиксировать версии toolchain и системные зависимости. Автоматическая сборка не заменяет ручную проверку окон, звука и ввода.

**Приёмка:** на каждой заявленной системе создать профиль, набрать RU/EN, сменить раскладку и режим, открыть/закрыть клавиатуру, выбрать внешний файл, перезапустить и проверить данные; отдельно проверить несколько мониторов, масштаб и звук. Проверить Linux X11 и Wayland отдельно: возможность задавать позицию окон зависит от композитора. Windows — обязательная первая проверка, Linux и macOS объявлять поддерживаемыми только после успешной сборки и ручного сценария. Минимальные версии ОС и наличие macOS-машины остаются открытыми.

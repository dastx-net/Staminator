# Установщик Windows и пользовательские ресурсы

Создать установщик Staminator с выбором установки для текущего пользователя или для всех пользователей. Ресурсы текущего пользователя подготовить при установке, а для других пользователей общей установки — при первом запуске приложения.

## Текущее состояние

- `apps/desktop/src/content.rs::ContentCatalog::load` ищет уроки рядом с исполняемым файлом, затем в дереве разработки. Фразы и раскладки оригинала ищутся в `src/stamina_setup`; рассчитывать на этот каталог в поставке нельзя.
- База хранится в `%APPDATA%/Staminator/staminator.sqlite3`, пользовательские фразы — в `Staminator/phrases`, фоны — в `Staminator/Backgrounds`. Встроенные переводы и фон включены в программу. Встроенные клавиатуры добавляются в коллекцию при запуске с маркерами установки.
- Состав ресурсов для распространения и права на них нужно проверить. Установленная Stamina и её личные данные в пакет не входят.

## Реализация

1. Выбрать и зафиксировать инструмент сборки установщика после проверки поддержки двух областей установки, обновления и удаления. Подготовить воспроизводимую сборку из release-артефактов без зависимости от дерева исходников и локальной установки Stamina.
2. В мастере предложить установку для текущего пользователя в `%LOCALAPPDATA%/Programs/Staminator` без повышения прав или для всех пользователей в `%ProgramFiles%/Staminator` с запросом прав администратора. Создать ярлык и запись удаления в соответствующей области. При отказе в повышении прав сообщить об ошибке и оставить возможность выбрать пользовательскую установку.
3. Составить явный список поставляемых файлов и назначений. В `Документы/Staminator` разместить стандартные и пользовательские уроки, фразы, клавиатуры и фоны. Необходимые начальные фразы подготовить с проверкой прав. Музыку и звуки пока не включать: ресурсов ещё нет, их поставка рассматривается в [плане аудио](audio.md). Встроенные переводы оставить в программе. Получать путь к «Документам» через Windows: папка может быть перенесена или находиться в OneDrive. Базу и настройки оставить в `%APPDATA%/Staminator`.
4. Для запускающего установку пользователя создать каталог ресурсов и сразу заполнить его начальными файлами. При установке для всех пользователей обеспечить ту же подготовку при первом запуске каждого другого пользователя от его имени, без записи в профиль администратора вместо его профиля. Использовать общий идемпотентный механизм и проверять результат; при ошибке показать причину и дать повторить подготовку.
5. При обновлении, восстановлении и повторной установке сохранять базу, профили, результаты и пользовательские ресурсы. Вести версионированный список установленных начальных ресурсов: добавлять новые файлы, но не перезаписывать существующие и не восстанавливать удалённые пользователем. При совпадении имени с пользовательским файлом сохранить его и сообщить о пропущенном ресурсе. Обновлённые версии существующих ресурсов предлагать отдельно, без автоматической замены. Учесть существующие маркеры клавиатур и миграцию прежних пользовательских данных в новые каталоги без потерь и молчаливой перезаписи. Создание схемы БД оставить приложению с его миграциями.
6. Обеспечить запуск без доступа на запись в каталог программы. Определить поведение при смене области установки и обнаружении другой копии: не оставлять неясных дубликатов и не переносить данные молча. Удаление по умолчанию сохраняет пользовательские данные; отдельное явное действие на их удаление относится только к текущему пользователю и показывает путь. Ошибки установки и удаления должны оставлять понятное состояние для повторной попытки.
7. Добавить инструкции сборки, установки, обновления, удаления и расположения данных; связать проверку с [QA](qa.md) и [поддержкой платформ](platforms.md). До публикации проверить лицензии приложения, зависимостей, инструмента установщика и каждого поставляемого ресурса.

## Приёмка

- На чистой Windows установить оба варианта, проверить путь, права, ярлык, запись удаления и запуск без дерева репозитория и установленной Stamina. Пользовательская установка работает без администратора; общая запрашивает повышение прав.
- Сразу после установки проверить состав пользовательского каталога. Во второй учётной записи проверить подготовку при первом запуске общей установки и отсутствие доступа к данным первого пользователя. Проверить пути с пробелами и кириллицей.
- Пройти урок, проверить доступные фразы, клавиатуры и фон; создать профиль и пользовательские данные, перезапустить приложение и проверить сохранение. Отсутствующий ресурс и ошибку записи проверить отдельно.
- Обновить и переустановить приложение с изменёнными и удалёнными пользователем ресурсами; проверить их сохранность, добавление новых ресурсов и работу существующей базы. Проверить отмену установки, отказ в повышении прав, недостаток места и повтор после ошибки.
- Удалить приложение, убедиться, что данные сохранились, затем отдельно проверить явное удаление данных текущего пользователя. Проверить смену области установки и повторную установку.

**Открыто:** инструмент установщика, точный перечень и источники начальных ресурсов, способ предложения их новых версий и переход между областями установки. До инвентаризации и проверки прав состав поставки не считать утверждённым.

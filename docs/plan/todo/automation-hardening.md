# Изоляция автоматизации: оставшиеся работы

Первая очередь сделана: [ADR 0009](../../adr/0009-untrusted-ci-branches.md). Остались меры, которым нужен root на easy-day и переделка бота.

## Codex отдельно от секретов бота

**Проблема:** Codex работает под `stamibot` с включённой сетью. Песочница Codex ограничивает запись, но не чтение. Ему доступны токен GitHub, ключ администратора тестовой VM, пароль пользователя `e2e` и вход Codex. Инструкция, внедрённая в issue, зависимость или веб-страницу, может увести их наружу.

**Предложение:**

- Учётка `stamicodex` для ходов Codex. `stamibot` хранит токен и ключи и запускает Codex через `sudo -u stamicodex` (одна строка в sudoers, без пароля, только `codex`).
- Рабочие деревья в общей группе: Codex пишет, бот читает и коммитит.
- `vm.py` для стадии `e2e` вызывается через обёртку под `stamibot` с фиксированным набором команд. Команды `ps` и произвольный `put` для Codex закрыть: сейчас это администратор VM.
- Сеть Codex ограничить списком: OpenAI, crates.io, GitHub на чтение.

**Открытые вопросы:** как Codex отдаёт файлы в VM без SSH-ключа; нужен ли ему GitHub вообще.

## Агент Jenkins без root-доступа

**Проблема:** `jenkins-agent` состоит в группе `docker`. Любая задача Jenkins и любой, кто меняет её pipeline, получает root на easy-day. Для Staminator это закрыто доверенным pipeline, для остальных задач нет.

**Предложение:** rootless Docker для `jenkins-agent` либо агент в отдельной VM libvirt. Проверить все задачи Jenkins: часть из них деплоит на сам сервер.

## Мелочи

- Убрать из публичных документов адрес и имя администратора тестовой VM, если это не мешает работе.
- Jenkins не сообщает статус сборки в GitHub, поэтому защита `master` не требует зелёного CI. Решить, нужен ли статус.

**Приёмка:** ход Codex не может прочитать токен GitHub и ключ VM; сборка любой задачи Jenkins не даёт root на сервере.

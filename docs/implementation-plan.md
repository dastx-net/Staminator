# План Rust-версии Staminator

Статус: рабочий план. Цель — нативное приложение для Windows с функциональным паритетом Stamina; возможность сборки для других настольных ОС сохраняем там, где это не усложняет воспроизведение поведения.

Текущий прогресс: основа workspace создана, окно запускается, первый урок и первая фраза доступны на русском и английском; метрики и пауза реализованы в отдельном ядре. Главный экран использует крупную прокручиваемую строку и локальный фон, экранная клавиатура открывается отдельным окном и скрывается через настройки или крестик. Остальные три режима, выбор контента, профили, сохранение результатов, редакторы, расширенные настройки и звук ещё впереди. Полный визуальный и поведенческий паритет с оригинальным `.exe` пока не подтверждён.

Для внешнего вида пользователь предоставил [скриншот урока](../src/materials/main_screen_ongoing_lesson_keyboard.png). Он задаёт ориентир для текущей итерации: текст крупный и показывается узким фрагментом по всей ширине окна, текущий символ находится около центра; экранная клавиатура — отдельное перемещаемое окно с полноразмерной раскладкой, зонами пальцев и подсветкой следующей клавиши. Пункт настроек управляет видимостью клавиатуры, закрытие её окна должно выключать этот пункт.

## Техническое решение

- Rust workspace: `crates/core` для правил набора и расчётов, `crates/stamina-data` для чтения исходных форматов и хранения новых данных, `apps/desktop` для окна приложения.
- Версия Rust закреплена в `rust-toolchain.toml`: 1.99.1.
- Интерфейс: `eframe`/`egui`, включая собственную отрисовку текста, экранной клавиатуры и графиков. Файловые диалоги: `rfd`. Декодирование старых файлов: `encoding_rs`. Звук: `rodio` после готовности основного сценария.
- Ядро не зависит от UI и часов системы: события ввода получают время явно. Это позволит сопоставить скорость, ошибки, паузу и завершение с оригиналом в тестах.
- Новые настройки и результаты храним отдельно от `src/stamina_setup` в пользовательском каталоге приложения. Импорт старых форматов будет отдельной операцией; установка Stamina остаётся неизменной.
- Старые аудио, изображения и исполняемые файлы не включаем в сборку автоматически. Сначала делаем собственные нейтральные ресурсы и проверяем права на перенос.

Выбор библиотек предварительный: после первого собираемого окна проверим их пригодность для горячих клавиш, ввода с русской раскладки и звука на Windows. Для окна взят `eframe` 0.37.0.

## Этапы и критерии готовности

| Этап | Результат | Проверка |
| --- | --- | --- |
| 0. Основа — выполнено | Первый Git-коммит, Rust workspace, документированный запуск, карта функций и форматов | `cargo test --workspace`, сборка и короткий запуск desktop-приложения; установка Stamina не затронута |
| 1. Основной набор — частично | Окно, старт/стоп/пауза, подсветка текущего символа, обработка верных и неверных клавиш, таймер, скорость, процент ошибок, экран результата | Автотесты ядра проходят; нужна ручная проверка ввода и сравнение с оригиналом |
| 2. Все пять режимов | Уроки, фразы, буквы из фраз, все клавиши, внешний текстовый файл; выбор/переключение уроков, продолжение файла | Повторяем набор на RU/EN; переходы между фрагментами и режимами; импорт образцов `Data/` |
| 3. Данные пользователя | Создание/выбор/переименование/удаление профиля, настройки, сохранение позиции и результатов, история с графиком | После перезапуска восстанавливаются данные; записи разделены по профилю и раскладке |
| 4. Редакторы и интерфейс | Редактор уроков, добавление фраз, параметры внешнего файла, отдельное окно экранной клавиатуры, раскладки, цвета, шрифты, скины, основные горячие клавиши | Пользователь создаёт урок и фразу, проходит их, меняет раскладку и оформление; переносит клавиатуру на другой монитор и скрывает через настройки или закрытие окна |
| 5. Звук и полировка | Звуки событий, плейлист, управление музыкой и громкостью, справка/информация, устранение расхождений | Ручное сравнение сценариев с установленной Stamina на отдельной копии; регрессионные тесты |

Копирование регистрации, ограничения пробной версии, встроенной логической игры и интеграций с программами переключения раскладки требует отдельного решения: эти функции не должны случайно попасть в продукт вместе с полезным тренажёром.

## Приоритеты исследования

1. Составить таблицу переходов состояний сеанса по `Stamina.cpp`, `MainWnd.cpp`, `TextField.cpp` и уточнить обработку пробела, Enter, Backspace, Esc и паузы.
2. Разобрать маркеры `lessons.*`, правила индексирования `phrases.*` и чтение внешнего файла; записать реальные примеры без переноса защищённого контента в тесты.
3. Уточнить алгоритмы режимов `MODE_MIXED_TEXT` и `MODE_EVENLY`, ограничения генерации и связь языка с раскладкой.
4. Зафиксировать настройки по страницам `PageGeneral`, `PageView`, `PageKeyb`, `PageSound`, включая значения по умолчанию.
5. Проверить оригинал на копии установленной папки: главный экран, редакторы, история, горячие клавиши, работа с несколькими раскладками. Сохранить скриншоты сравнения только после проверки прав на их распространение.

## Организация работы

- Простые изолированные задачи реализации (парсеры, модели, отдельные компоненты UI) можно передавать агенту Luna. Архитектуру, интеграцию, проверку паритета и решения по расхождениям ведёт основной агент.
- Каждый этап должен завершаться работающим пользовательским сценарием. Изменения исходной Stamina и её установленной папки для этого не требуются.
- После первого запуска уточнить фактический объём паритета в таблице: подтверждено исходниками, подтверждено запуском, реализовано, проверено.
